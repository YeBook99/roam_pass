# ROAMPASS

여행자용 데이터 SIM(이심·유심) 판매 서비스의 **결제 → 발급 → 어드민 확인 → 설치 추적** 흐름을 구현하는 과제입니다.

> 작성 중입니다. 지금은 **결제, 이심 발급, 설치 추적, 어드민 조회의 기본 흐름**까지 동작하고, 사용자 화면(http://localhost:3000)과 어드민 화면(`/admin`)이 있습니다. 정상 경로를 먼저 끝까지 만들고, 예외 처리는 결제 이후부터 하나씩 보완하는 순서로 진행하고 있습니다.

## 실행 방법

필요한 것: git, Docker

```bash
git clone https://github.com/YeBook99/roam_pass.git && cd roam_pass
cp .env.example .env
docker compose up -d --build --wait
```

확인: `curl localhost:8080/actuator/health` → `{"status":"UP"}`, 화면 http://localhost:3000

정리: `docker compose down -v`

## 배포 (준비 중)

AWS EC2 한 대에 `docker-compose.prod.yml`로 Caddy(HTTPS), 화면, 서버, PostgreSQL을 함께 띄웁니다. DB도 컨테이너이고 RDS는 쓰지 않습니다(ADR-12).
설정 파일은 준비했고 로컬에서 같은 구성으로 확인했습니다. **아직 EC2에 올리지 않았습니다.** 절차는 [L5 배포 가이드](docs/learn/L5_AWS_프리티어_배포.md)에 있습니다.

## 현재 한계 (작업 중, 보완 예정)

- **발급 재요청이 없습니다.** 공급사 발급 요청이 실패하거나 콜백이 오지 않으면 주문이 `ISSUING`에 남습니다. 재요청(최대 3회) → `ISSUE_FAILED` → 자동 환불은 다음 보완 단계에서 만듭니다
- **같은 멱등키 결제 요청이 거의 동시에 여러 번 오면 일부가 409(`PAYMENT_IN_PROGRESS`)를 받습니다.** 같은 키 3건 동시 요청을 25번 반복했을 때 75건 중 13건이었습니다. 결제는 1건만 만들어지고 PG도 한 번만 불리지만, "같은 키면 기존 결과를 돌려준다"는 설계와 다릅니다. 원인(부분 유니크 인덱스와의 경합으로 추정)을 확인해 보완 단계에서 고칩니다
- **필수 테스트 중 T2(중복 콜백 동시성)·T3(결제됐는데 발급 실패)는 아직 없습니다.** 위 보완과 함께 추가합니다. T1(중복 결제 통지 동시성)은 있습니다
- 15분 넘게 결과를 모르는 결제(`READY`)와 결제 대기 만료(`PENDING → EXPIRED`)는 어드민·만료 단계에서 다룹니다
- **어드민은 주문 목록(필터·페이지)과 상세 타임라인만 있습니다.** 타임라인은 상태 이력(`status_history`)만 보여 주고, 웹훅·콜백 수신 기록은 아직 붙이지 않았습니다. 이상 건 모아 보기와 운영자 조치(수동 환불·발급 재시도)는 보완 단계입니다. 화면은 http://localhost:3000/admin 입니다
- **사용자 화면은 요금제 → 주문 → 결제 → 발급 대기 → 내 SIM까지 있습니다.** 환불 버튼, 유심 ICCID 입력, 모의 PG 시연 설정 화면은 없습니다. 설치 코드는 QR 이미지가 아니라 문자열(폰 설정에서 직접 입력)로 보여 줍니다
- **설치 추적은 공급사 조회만 씁니다.** 설치 콜백 수신, SIM별로 조회 주기를 다르게 하는 선택적 폴링, 기기에서 삭제(`DELETED`), 환불 직전 동기 조회는 보완 단계입니다. 지금은 개통 전 SIM을 모두 1분마다 조회합니다
