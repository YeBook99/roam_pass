# README 8개 질문 답변 갱신

과제에서 "가장 중요한 줄"이다 (2.5). 원재료: `docs/ANSWERS_DRAFT.md`, `docs/DECISIONS.md`, `docs/LEARNING_LOG.md`, 실제 코드, 테스트 출력.

## 원칙
- **근거 없는 문장 금지.** 각 답의 주장마다 코드 위치(`파일:줄`)나 테스트 이름을 붙일 수 있어야 한다.
- 초안의 `【교체】` 는 실제 값으로 바꾼다: 파일 경로, 설정값(타임아웃·재시도 횟수·폴링 주기), 테스트 로그, 배포 URL.
- `【본인】` 칸(Q1의 개인적 이유, Q7 전체, 인터뷰 개인 경험)은 **대신 쓰지 않는다.** LEARNING_LOG 내용을 정리해 "초안 제안"으로 보여 주고 사용자가 확정한다.
- 구현과 다른 초안 문장은 구현에 맞게 고치고, 설계에서 바뀐 이유를 한 줄 덧붙인다.
- 미구현·타협은 숨기지 않는다 → "미구현 / 타협한 부분" 섹션에 이유와 함께.

## 절차
1. `cd backend && ./gradlew test` 를 실제로 실행. 동시성 테스트 출력(테스트 이름, 통과, 검증한 숫자)을 Q3에 붙인다. 실패하면 README 작업을 멈추고 알린다.
2. Q1~Q8 각각: 초안 → 코드 확인 → 갱신. 다이어그램(mermaid 상태도, ERD 표)은 실제 enum·스키마에서 다시 뽑는다.
3. README 필수 섹션 존재 확인 (2.5-3): 실행 방법(복붙 가능한 커맨드) / 8개 질문 / 시연 방법(모의 PG·공급사 실패·지연·중복 켜기, INSTALLED·ENABLED 전환) / 배포한 곳·이유·막힌 지점 / 아키텍처·데이터 모델·상태 전이도 / 미구현·타협 / 실제 투입 시간·AI 사용처.
4. 변경 요약을 보여 주고 `docs(readme): …` 로 커밋.
