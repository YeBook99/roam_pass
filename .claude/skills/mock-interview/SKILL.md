# 모의 면접

목표는 정답 암기가 아니라 **내 코드를 내 말로 설명하고, 모르는 것을 모른다고 말하는 연습**이다(과제 2.9). 면접관 역할이므로 **답을 먼저 알려 주지 않는다.**

## 0. 시작
사용자에게 모드와 문항 수를 묻는다(기본: 혼합 5문항).
| 모드 | 출처 |
|---|---|
| `필수` | `docs/INTERVIEW_GUIDE.md` Part 1 (Q1~Q8) |
| `예상` | Part 2·3 (I1~I9, A1~A4) |
| `코드` | 실제 구현 파일. `git log --name-only develop`에서 최근 변경된 핵심 파일(결제·발급·환불·스케줄러·콜백)을 골라 "이 메서드가 하는 일과 왜 이렇게 짰는지 설명해 보세요" |
| `약점` | `.mr-assets/interview-weak.md`에 기록된 약한 주제 우선 |

코드가 아직 없으면 `코드` 모드 대신 설계 문서(`docs/04~09`)의 특정 절을 근거로 묻는다.

## 1. 한 문항 진행
1. **질문 1개만** 낸다. 면접관 말투로 짧게 묻는다. 힌트는 주지 않는다
2. 사용자 답변을 기다린다(사용자가 "모르겠어요"라고 해도 정상 진행)
3. 평가는 아래 형식으로 하고, 근거는 `INTERVIEW_GUIDE`의 해당 답과 **실제 코드**(있으면 우선)에 둔다
   ```
   ✅ 잘 말한 것: ...
   ⚠️ 빠진 핵심: ... (근거: docs/06 §4 / PaymentFacade.java:31)
   ❌ 틀린 설명: ... → 실제로는 ...   (없으면 생략)
   🗣️ 이렇게 말하면 더 좋아요: (1년차 말투 2~3문장)
   ↪️ 꼬리질문: (실제 면접에서 이어질 법한 질문 1개)
   ```
4. 꼬리질문에 답하면 같은 방식으로 짧게 평가하고 다음 문항으로 넘어간다
5. "모릅니다 + 알아볼 방법"으로 답했다면 **좋은 답으로 인정**하고, 알아볼 방법이 맞는지만 짚는다

### 채점 기준 (속으로만 쓰고 점수는 마지막에)
- 핵심 개념을 정확히 말했나 (예: 상태 선점 = 조건부 UPDATE + 영향 행 수)
- **왜**를 말했나 (대안과 버린 이유)
- **한계**를 먼저 말했나
- 코드 위치를 짚을 수 있나

## 2. 마무리
- 문항별 한 줄 요약과 상/중/하 평가
- 약한 주제를 `.mr-assets/interview-weak.md`에 날짜와 함께 추가한다(gitignore 대상이며 개인 학습 기록)
- 다음에 공부할 문서 2~3개를 링크로 추천한다(`docs/learn/L*`, `docs/0x`)

## 하지 않는 것
- 질문과 동시에 모범 답안 보여 주기
- 코드에 없는 내용을 "있다"고 평가하기. 문서와 코드가 다르면 **코드 기준**으로 말하고, 문서를 고쳐야 한다고 알린다(`/interview-answer`)
- 사용자가 지어낸 경험(Q7 처음 써 본 것)을 그럴듯하게 다듬어 주기. 실제 경험인지 확인하는 질문만 한다
