# 인터뷰 답변 스크립트 작성

2차 전형은 제출 코드를 함께 열어 보는 60분 인터뷰다. "깨지는 코드를 문제없다고 하는 것"이 가장 낮은 평가다.

## 답변 틀 (질문마다 동일)

```markdown
### Qx. <질문 원문>

**30초 답변**
> 면접에서 그대로 말할 수 있는 3~5문장. 1인칭, 쉬운 단어.

**왜 그렇게 했나**
- 근거 / 고려한 대안 / 버린 이유

**문서·코드 위치**
- 설계: docs/0x_...md
- 코드: `패키지.클래스#메서드` (구현 후 채움)

**예상 꼬리질문**
- Q: ... → A: ...

**한계 인정**
> "~한 상황에서는 ~가 깨질 수 있다는 걸 알고 있습니다. 시간상 ~로 두었고, 고친다면 ~하겠습니다."

**스스로 점검** (내 말로 설명할 수 있나?)
- [ ] ...
```

## 작성 원칙

- 처음 나오는 용어는 `docs/learn/` 링크를 달거나 괄호로 짧게 풀어 쓴다
- 과장하지 않는다. 테스트하지 않은 것을 "보장된다"고 쓰지 않고 "~로 막으려 했다"라고 쓴다
- 코드와 문서가 다르면 **코드를 기준으로** 문서를 고친다. 코드가 틀렸다면 사용자에게 알린다
- 사용자 본인 경험(Q7 처음 써 본 것, 투입 시간, 막혔던 지점)은 **대신 지어내지 않는다**. `> ✍️ 직접 작성:` 빈칸과 예시로 남긴다
