# 1년차 말투로 설명하기 (인터뷰 대비)

과제 평가의 30%가 "본인 코드를 설명할 수 있는가"이고, 2차 인터뷰는 제출 코드를 같이 열어 본다.
목표는 **사용자가 이 설명을 자기 말로 다시 말할 수 있게** 하는 것이다.

## 절차
1. 인자로 받은 대상(파일 / 클래스 / 메서드 / "결제 흐름" 같은 흐름)을 실제 코드에서 읽는다. 추측으로 설명하지 않는다.
2. 아래 틀로 설명한다. 어려운 용어는 바로 뒤에 괄호로 쉬운 말.
3. 결과를 `docs/interview/<주제>.md` 에 저장(있으면 갱신). 파일 맨 위에 대상 커밋 해시를 적는다 (`git rev-parse --short HEAD`).
4. 마지막에 사용자에게 **꼬리 질문 하나를 실제로 물어보고**, 답을 들으면 빠진 부분만 짚어 준다.

## 설명 틀
```
## 한 줄 요약
(이 코드가 없으면 무슨 일이 생기는지로 설명)

## 흐름 (번호 목록, 파일:줄 링크)
1. …

## 왜 이렇게 했나
- 선택: … / 버린 것: … / 이유: …

## 이런 상황에서는? (실패 시나리오 2~3개)
- 동시에 두 요청이 오면 → …
- 외부 호출이 타임아웃 나면 → …

## 한계 (솔직하게)
- "이런 상황에서는 깨질 수 있지만 시간상 이렇게 뒀다"

## 예상 꼬리 질문
- Q. … / 답의 핵심: …
```

## 말투 규칙
- "~입니다 / ~했습니다", 동료에게 설명하듯. 과장 금지 ("완벽하게 막았다" X → "이 경우까지는 막았다").
- 코드에 없는 기능을 있다고 말하지 않는다. 모르면 "코드상 확인이 안 됩니다"라고 쓴다.
- 관련 질문이 GUIDE 2.9 인터뷰 질문과 겹치면 그 질문을 꼬리 질문에 포함한다.
