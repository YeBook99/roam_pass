# 설계 결정 기록 (ADR)

과제의 "기술 선택 근거"(15%)와 Q1은 **무엇을 골랐는지가 아니라 왜 골랐는지**를 본다. 결정이 생길 때마다 바로 기록한다.

## 형식 (docs/02_기술선택_ADR.md 끝에 추가)

```markdown
### ADR-NN. <결정 제목>

- **상태**: 채택 / 대체됨(ADR-MM) / 보류
- **맥락**: 어떤 문제 때문에 결정이 필요했나 (과제 문서 번호)
- **결정**: 무엇을 골랐나 (한 문장)
- **고려한 대안**
  | 대안 | 장점 | 버린 이유 |
  |---|---|---|
- **근거 (1년차 말투)**: "저는 ~ 때문에 ~를 골랐습니다." "익숙해서"라면 그렇게 쓴다
- **처음 써 봄?**: 예/아니오. 예라면 어떻게 익혔는지(공식 문서/예제/AI, 걸린 시간) → Q7로 연결
- **한계와 바꿀 조건**: 어떤 상황이 되면 이 결정을 바꿔야 하나
```

## 절차

1. 기존 ADR과 겹치는지 확인한다. 기존 결정을 바꾸는 경우, 기존 ADR은 상태를 "대체됨"으로 바꾸고 새 ADR을 추가한다
2. 작성 후 `docs/INTERVIEW_GUIDE.md`의 Q1(기술 선택), Q7(처음 써 본 것)에 반영이 필요한지 확인한다 → `/interview-answer`
3. CLAUDE.md의 "확정된 기술 스택"이 바뀌었으면 함께 수정한다
4. 같은 커밋으로 남긴다 (`docs(arch): ...`)
